ASTER CARE — FREE MEDICAL HTML TEMPLATE
Version 1.0.0 | 25 October 2026

START HERE
Open index.html in a modern browser. Keep assets/ beside it. This is a
finished static HTML, CSS and vanilla JavaScript website. No React, Vite,
Node.js, npm install, build step, API keys or database is required. Images,
fonts and the Lenis scrolling library are bundled locally, not on a CDN.

WHAT THIS TEMPLATE DEMONSTRATES
A fictional family-practice landing page with service accordions, a care
philosophy, first-visit steps, practice information, FAQs and a local visit-
request draft dialog. The stock people are illustrative, not Aster staff
or patients. Services, business identity, address and hours are examples.
There are no ratings, patient counts, clinical advice or real availability.

The identity is a design demonstration, not a trademark-availability claim.
Replace illustrative business and medical-service content with accurate,
appropriately reviewed information before operating a real practice site.

FUNCTIONALITY
- Every main CTA has a real section or visit-draft action.
- Accessible native radio options for general visit/contact preferences.
- Browser name/email validation; draft review and clipboard/manual-copy.
- Independent smooth desktop scrolling in page, navigation and dialog.
- Native touch/reduced-motion fallback and keyboard/drag slim scrollbars.
- Mobile navigation uses one morphing control, Escape, focus containment
  and return, background scroll lock and independently scrollable content.
- Native details/summary enhanced with measured reversible height motion.
- Sticky compact service column on suitable desktop viewports.

IMPORTANT: REQUESTS ARE NOT SENT
The visit form builds a draft only. No appointment is booked, no request
is sent, and no patient portal, provider notification or backend exists.
No localStorage/cookie/analytics code is included. Inputs remain in the
current document until it is reloaded/closed; no database is used.

Do not enter or collect symptoms, health records or sensitive medical
information in this demonstration. Only name, email and broad preferences
are requested. To use a real booking workflow, connect a properly secured
booking/contact service and review privacy/security requirements for your
jurisdiction. Never embed service passwords or private API keys in JS.
Do not imply successful booking unless the actual backend confirms it.

EDITING
1. Edit headings, copy, service labels, FAQs, address and hours in index.html.
   Stable anchors: top, care, everyday, family, wellbeing, our-way,
   first-visit, practice, faq and request.
2. Named color/type/spacing tokens are at the top of assets/css/aster.css.
   The template has one intentional light/blue theme, no hidden dark mode.
3. Replace original SVG identity and stock images with your own licensed
   brand/practice material. Update alt text and image width/height.
4. Visit requests open from data-request anchors. An optional exact value
   selects its matching radio: Everyday health / Family care /
   Routine check-in. Keep the radio values and contextual CTAs consistent.
5. Keep keyboard focus, native radio inputs and real labels intact. Do not
   remove reduced-motion or no-JavaScript fallbacks when restyling.
6. Source is fully readable and locally editable. There is no minified
   application build; only the unchanged third-party library is minified.
7. Ensure all your own legal, privacy and contact details are accurate before
   using the template publicly. The example practice is not a real clinic.

LOCAL HTTP PREVIEW (OPTIONAL)
With Python installed, open a terminal IN this folder and run:
  python -m http.server 4211 --bind 127.0.0.1
Open http://127.0.0.1:4211/ . Stop the server with Ctrl+C.
An editor's static-preview extension also works. Neither Python nor Node
is required on the final static hosting account.

UPLOAD TO YOUR DOMAIN ROOT
1. Back up any existing site before replacing its files.
2. In cPanel/File Manager or FTP, upload the CONTENTS of this folder into
   the domain's document root (often public_html). index.html should be
   directly beside assets/, not inside an unintended extra nested folder.
3. Retain LICENSE, licenses/ and notices with the distributed template.
   docs/ is supporting material and may stay private; it is not a runtime
   dependency. Keep README.txt for the person maintaining the site.
4. Enable HTTPS through your host. No Node process, SPA rewrite, database
   migration, framework build or server-side application is required.
5. Visit the domain and verify images/fonts, anchors, mobile navigation,
   keyboard focus, accordion reversals, request dialog and your real contact
   integration (if you connect one). This draft alone never sends data.

UPLOAD TO A SUBFOLDER
Upload the same contents into e.g. public_html/aster-care/ and visit
https://your-domain.example/aster-care/ . All assets use relative paths.
No source rebuild/base configuration is needed. Keep the final URL slash.

STATIC HOSTS
Publish the directory containing index.html on a static host such as
GitHub Pages or Netlify. Build command: none. Publish directory: this folder.
Configure custom domain/DNS/HTTPS through the selected hosting provider.
Do not upload private hosting credentials into this folder.

NATIVE FALLBACKS
Without JavaScript the care content, navigation, hours, section links and
native FAQs remain usable. The request section explicitly explains that
the draft dialog requires JavaScript; no form submits elsewhere. If native
dialog support is absent, request links lead to that same informative
section. If Lenis is missing, native page/region scrolling remains usable.
Touch scrolling stays native; reduced motion disables smoothing/reveals.
